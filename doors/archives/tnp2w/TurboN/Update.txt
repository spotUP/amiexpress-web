v2.w  [PRIVATE RELEASE]
----
New Stuff
 ·New sysop command: [E]dit Descriptions! Now TN is finally complete!
 ·New [g]rabDIR option: [T]hisScan, for grabbing via ZMODEM the current
  scan starting from the date you picked.  Thanks to Diablo for tip.
 ·Added new option for [f]lags: [A]uxiliaryFlags, which lets you scroll

  the line a file was not found in the paths.

v2.v  [PRIVATE RELEASE]
----
New Stuff
 ·New command! [G]rabDIR, this lets your leech users grab the DIR listings
  via ZMODEM! This way they don't tie up the computer for 5 hours looking
  at each listing page by page. Thanks to Shatterstar for this excellent
  idea. If for some reason u don't like this option, let me know, since
  I assume DIR listings are public. There are no security level
  restrictions on this option.
 ·Added "press any key" pause prompts to all sysop commands. This comes
  in handy when working with multiple files.
 ·Added text for each sysop command, i.e. "Choose files to move", etc. So
  you know which command is being executed (move, copy, nuke, and so on).

Fixed
 ·The nuker wasn't working if you didn't have a "Node0/Callerslog". It works
  ok now. Thanks to Papillon for pointing this out.
 ·Fixed a nasty little bug that would cause the high ASCII bit to be
  stripped when using TN from remote during [c]omment. This would result
  in a screen full of gibberish.
 ·I think I may have fixed some unexplained crashes. I forgot to set a
  boundary limit on the main scroller matrix. Thus, if one of the lines
  in the DIR list exceeded 210 characters (extremely rare!), the program
  would crash.  Thanks to Jordan for all his help in this matter.
 ·the filehelp.txt routine wasn't checking for filehelp.txt.gr. Now it
  checks for [.gr] first, then .txt, and if none are found, a warning
  message is given. I guess I was just lazy to not have done this
  right the frist time around!
 ·Directory prompt was only allowing 1 digit (0-9). Fixed it to 2 digits,
  so you can have (0-99) directories. Thanks to IlluVaTaR for tip.

v2.c  BETA
----
New Stuff:
 ·NZO speeded up the scanner algorithm by a factor of 4!
  There ya go Raj-Ban, no more 10 second waits! Super Turbo Newscan!
 ·Turbo Newscan is now polymorphic! This means that you can use it
  as your 'f' command as well as your 'n' command in /X! At the moment
  it does not display the *.gr file menu. Final version will.
 ·Implemented the [D]estroy and [F]reeDownload commands.  I got rid of
  all the others in the menu.  I will add them as they become available.
 ·I finally got around to adding the pause prompt at end of the listing!
 ·Added a cool percentage ratio of where the listing is currently at.
 ·Optimized the program a little. Basically I removed all array subscripts
  and replaced them with faster pointer arithmetix.  Probably not
  noticeable on faster machines.

Fixes:
 ·The [C]ommenter was not working on multiple files properly. At the
  moment, all sysop commands exit the door after each file procedure.
  Future versions will work on multiple files.
 ·Fixed bug that had strange ANSI effects when you tried to move the cursor
  when there was only one file in the listing/screen.
 ·Fixed bug that would not count all the bytes in a description if it was
  over 1 meg. Thanks for noticing Maddy!
 ·Fixed NS (non-stop) bug that would crash the program.
 ·By popular demand, the ">" has been removed and I am no longer shifting
  the scroll by 1 byte. In order to accomodate non-ANSI users, however, I
  have put a new "<" next to the filename when flagging--without a change
  in the DIR format. This way everyone is happy!
 ·Fixed bug that would sometimes give unexpected results when entering a
  Ne[w] Date.
 ·The scanner algorithm doesn't check for [c]entury date, it simply jumps
  to byte 0, so it should be instant now. Why didn't I think of this before??
 ·People were complaining of the slow scroll speed, but the reason for
  this is so that my run-time execution has a chance to catch any
  CTRL-C's.  I have used a Delay(1) [one jiffie] between every line when
  using NS.  During regular scrolling, there is no delay.  The final version
  will make this option configurable.  Just hang in there!
 ·Fixed obscure bug that would show "Total Bytes" banner even after
  using a ne[w] date. This happened if you did a ne[w] date and the scroll
  was right about to give the banner info. So many little details!
 ·NZO fixed bug in scanner routine. It won't skip dates any more. As I
  write this, he is making a faster version of it.
