**RESEARCH FINDINGS** (2025-12-02 Deep Dive):

**Test Results** - All SIM doors fail with same pattern:
- WHO (14KB): PC jumps to ROM at 0xf00080, accesses absolute address 0x790
- WHAT (15KB): PC jumps to ROM at 0xf00080
- RTW (20KB): PC jumps to ROM at 0xf00080
- **Pattern**: All crash early in execution, before any functional code runs

**WHO Door Analysis** (Detailed Disassembly):
```asm
Address 0x1154: movea.l 0x790.l, a0  ; Load function pointer from ABSOLUTE address 0x790
Address 0x115a: jsr (a0)              ; Call function
Address 0x115c: tst.l d0              ; Test return value
```

WHO calls this function multiple times with different string parameters (0x794, 0x79c, etc.). The function at 0x790 appears to be a string processing or output function that the door expects the BBS to provide.

**Critical Discovery** - SIM doors expect **pre-configured function tables**:
- WHO expects function pointer at absolute address 0x790
- This is NOT set up by express.e (confirmed by reading express.e:4231-4544)
- Express.e just launches SIM doors and returns - no environment setup
- This suggests SIM doors were written for a DIFFERENT BBS system or custom environment

**Memory Layout Issue**:
- WHO's CODE segment: 0x1008-0x3d94 (11,412 bytes)
- WHO's DATA segment: 0x3d08-0x4a1c (3,348 bytes)
- Address 0x790 is BELOW code start - unmapped in our emulator
- Value at binary offset 0x790: 0x011041ec (not a valid code address in WHO)

**AmiExpress Doesn't Provide**:
- No function tables in low memory for SIM doors
- No shared memory regions
- No BBS API via absolute addressing
- Just startProcess() and immediate return

**WHY SIM Doors Need Full OS Emulation**:

1. **Amiga CLI Environment Required**:
   - Low memory (0x0-0x1000): Exception vectors, system structures
   - CLI/Process structures with valid pointers
   - Segment lists, environment variables
   - Shell/WorkBench startup structures

2. **Function Vector Tables**:
   - SIM doors expect BBS functions at fixed absolute addresses
   - These are NOT standard Amiga OS calls - they're BBS-specific
   - May be from pre-AmiExpress era or different BBS software

3. **Shared Memory Protocol**:
   - SIM doors may use shared memory instead of message passing
   - Need to identify memory regions and data structures
   - Requires reverse engineering each door's expectations
